# BookTrack

Frontend MVP личной библиотеки по ДЗ4: просмотр, добавление, редактирование,
подтверждаемое удаление, статусы, поиск по названию/автору и фильтрация.
React + TypeScript + Vite + Tailwind CSS; Vitest + React Testing Library.
UI основан на [Minimal Library](docs/ui_concepts/ui_description.md).

## Запуск

Нужны Node.js и npm. Реализация проверяется в имеющейся среде Node 18.15 / npm 9.5;
для новой среды предпочтителен поддерживаемый Node 22 LTS.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173).
Изменения исходников подхватываются через HMR.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

Дополнительная браузерная проверка после `npm run build`: `npm run check:browser`. Она сама запускает
локальный Vite на 5173 и установленный Edge в headless-режиме, проверяет размеры
и сценарии, проверяет запуск production-сборки, сохраняет скриншоты и JSON в `docs/images/hw4/`, затем закрывает процессы.
Порт 5173 должен быть свободен. Для другого браузера задайте переменную окружения
`BOOKTRACK_BROWSER_PATH` с путём к установленному Chromium/Chrome/Edge.

`dist/` — готовая статическая сборка. В Windows при запрете выполнения npm.ps1
используйте `npm.cmd` вместо `npm`.

## Данные и демонстрационные состояния

Три исходные книги загружаются из mock-массива с задержкой 450 мс.
Все изменения живут **только в памяти** и сбрасываются при перезагрузке страницы.
Авторизации, API, базы данных, Supabase и LocalStorage нет.

В dev-режиме доступны детерминированные сценарии:

- `/?empty` — пустая библиотека.
- `/?mockError=list` — первая загрузка завершится ошибкой, «Повторить» сработает.
- `/?mockError=create` — первое добавление завершится ошибкой до записи; повтор сохранит книгу.
- `/?mockError=update` — первый отказ редактирования.
- `/?mockError=remove` — первый отказ удаления.

Параметры можно сочетать, например `/?empty&mockError=create`.
В production-сборке эти параметры не управляют данными. Задержки и отказы тестов
настраиваются непосредственно в `createMockRepository`, без сети и случайности.

## Структура

- `src/domain/` — Book/BookInput, статусы, нормализация, валидация, поиск и сортировка.
- `src/data/` — контракт BookRepository и асинхронный mock-адаптер.
- `src/components/` — карточка, общая форма, диалог и подтверждение удаления.
- `src/hooks/` — блокировка повторных асинхронных действий и состояния записи.
- `src/App.tsx` — библиотека, поиск/фильтр и связь UI со слоем данных.
- `*.test.ts(x)` — проверки поведения, ошибок и границ.
- `docs/` — [документы ДЗ2/ДЗ3](docs/README.md), [ТЗ](docs/technical_specification.md),
  [отчёт ДЗ4](docs/development_report.md).

Роутер не нужен для одного экрана. Смена статуса выполняется через редактирование.
Оценка доступна только при «Прочитано» и очищается при переходе в другой статус.
Поиск и фильтр сохраняются после записи; если книга скрыта, интерфейс предлагает сброс.

Публикация на GitHub и хостинг не выполняются автоматически. Для сдачи загрузите
репозиторий на GitHub и приложите ссылку; локальный запуск соответствует варианту
сдачи исходного задания. Оставшиеся ручные проверки описаны в отчёте.
