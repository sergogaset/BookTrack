# BookTrack — персональная библиотека

[Навигация](README.md) · [Истории](user_stories.md) · [Техническое задание](technical_specification.md) · [UI-концепции](ui_concepts/ui_description.md)

## 1. Название и краткая идея

BookTrack — небольшое учебное веб-приложение для персонального учёта книг. Читатель хранит собственный список и отмечает, что хочет прочитать, читает сейчас и уже закончил. Это описание — единый источник продуктового контекста для ДЗ2 и ДЗ3; приложение пока не реализовано.

## 2. Проблема пользователя

Списки в заметках и память не дают быстро восстановить планы чтения. После перерыва трудно найти сохранённую книгу и понять, на каком этапе чтение остановилось. Пользователю нужен простой каталог без социальных и рекомендательных функций.

## 3. Ценность решения

Одна библиотека объединяет планы и результаты чтения. Статусы помогают определить следующий шаг, а поиск по названию и автору возвращает к нужной записи. Необязательные оценка и заметка сохраняют личное впечатление без сложного дневника.

## 4. Целевая аудитория и персоны

Основная персона — регулярный читатель Анна: добавляет книги, меняет статусы и иногда оставляет заметку. Дополнительная персона — возвращающийся читатель Сергей: после перерыва ищет ранее сохранённую книгу по части названия или автору. Это два сценария одного пользователя, с одинаковыми правами. ДЗ4 демонстрирует одну локальную библиотеку; ДЗ5 изолирует библиотеки зарегистрированных пользователей.

## 5. Ключевые функции MVP

1. Просмотр библиотеки с названием, автором и статусом.
2. Добавление книги с обязательными названием, автором и статусом.
3. Редактирование записи, включая необязательные оценку и заметку.
4. Удаление выбранной книги после подтверждения.
5. Изменение статуса: «Хочу прочитать», «Читаю», «Прочитано».
6. Поиск по части названия или автора.
7. Фильтрация по статусу совместно с поиском.

## 6. Границы и ограничения MVP

Не входят социальная сеть, друзья, подписки, AI-рекомендации, внешний каталог, загрузка обложек, ISBN, жанры, платежи, сложная статистика и административная панель. Жанры и статистика из исторического [отчёта ДЗ1](report_1.md) не расширяют текущий MVP. Счётчики статусов допустимы в концепции Dashboard как представление того же списка.

ДЗ3 ограничено документацией и изображениями. ДЗ4 использует данные в памяти, сбрасываемые после перезагрузки; постоянное хранение и авторизация появятся в ДЗ5. Оценка доступна только для прочитанных книг; при возврате в другой статус она очищается с пояснением. Повторяющиеся названия и авторы допустимы. Подробные проверяемые ограничения перенесены в ТЗ.

## 7. Типовой пользовательский сценарий

Читатель открывает библиотеку → нажимает «Добавить книгу» → вводит название и автора → сохраняет со статусом «Хочу прочитать» → позднее находит запись поиском → переводит в «Читаю», затем в «Прочитано» → при желании добавляет оценку и заметку. Ошибки не стирают ввод; удаление требует отдельного подтверждения.

## 8. Краткое описание данных

Книга содержит `id`, `title`, `author`, `status`, необязательные `rating` и `notes`, даты `created_at` и `updated_at`. Коды статусов: `want_to_read`, `reading`, `finished`. Название — 1–200 символов после trim, автор — 1–120, заметка — до 1000, оценка — целое 1–5 либо отсутствие значения. С ДЗ5 добавляется обязательный `user_id` владельца для RLS. Служебные поля пользователь не редактирует; дополнительных предметных таблиц не требуется.

## 9. Технологический стек

Среда: VS Code, OpenAI Codex и ChatGPT. Frontend: React + TypeScript + Vite, Tailwind CSS. Тестирование: Vitest + React Testing Library; при необходимости позднее Playwright. Данные и доступ с ДЗ5: Supabase PostgreSQL + Auth + RLS. Репозиторий и автоматизация: GitHub + GitHub Actions; размещение — Vercel. На ДЗ3 зависимости не устанавливаются.
