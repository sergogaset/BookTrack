Принято решение следовать формату сдачи и используемому Codex: rules.md — сдаваемый артефакт, правила передаются явным чтением, автоматическое подключение не заявляется. Фиктивный файл Cursor и инструкции вне docs/ не создавались. Если преподаватель требует именно `.cursorrules`, уточнить формат сдачи отдельно; это не означает, что Codex его автоматически применяет.

Для будущей задачи передайте запрос: «Прочитай docs/project_description.md, docs/technical_specification.md и docs/rules.md; примени правила к текущему этапу». Для A/B используйте независимые стартовые условия из testing.md, не выдавайте текущую сессию за два независимых запуска.

## Выявленные противоречия и принятые решения

- Жанры/статистика в ДЗ1 → исключены актуальным минимальным MVP; исторический отчёт не переписан.
- Имя project-context.md и технический объём краткого описания → единое project_description.md и подробное ТЗ, без старого дубля.
- Статус «оригинал ДЗ2 не найден» → исправлен по найденному original.txt; имена сверены с ним.
- Различия Codex/Cursor → rules.md и явное чтение, без заявлений о работающей конфигурации Cursor.
- Неопределённый минимум ДЗ4 → просмотр, добавление, поиск; остальные функции завершить в ДЗ5. Полный MVP на изображениях не означает обязательность всей реализации в ДЗ4.
- Лимиты, сброс оценки, mock в памяти → приняты как явные учебные решения; технические детали в ТЗ. Новые роли/таблицы не добавлены.
