# Контекст проекта BookTrack

[Навигация по ДЗ2](README.md)

## Проблема, цель и аудитория

Пользователю трудно помнить, какие книги он планировал прочитать, читает сейчас или уже закончил. Цель BookTrack — хранить личный список с понятными статусами и быстро находить запись по названию или автору.

На первом этапе аудитория — один пользователь. На ДЗ5 планируется отдельная библиотека каждого зарегистрированного пользователя. Все требования ниже описывают целевое поведение; приложение ещё не реализовано.

## Границы MVP

В MVP входят список книг, создание, редактирование, удаление с подтверждением, три статуса, поиск и фильтр. Оценка и короткая заметка — необязательные поля книги.

Исключены ISBN, обложки, внешние книжные API, жанры, друзья, социальная лента, AI-рекомендации и сложная аналитика. Жанры и статистика, упомянутые в [ДЗ1](report_1.md), не являются требованиями текущего MVP. Авторизация и RLS появятся только на ДЗ5.

## Функциональные требования

| ID | Проверяемое требование |
| --- | --- |
| FR-01 | Список показывает название, автора и русскую подпись статуса каждой книги; при отсутствии книг предлагает добавить первую |
| FR-02 | Добавление принимает title, author, status, необязательные rating и notes; после успешного сохранения новая запись появляется в списке ровно один раз |
| FR-03 | Редактирование открывает текущие значения; успешное сохранение обновляет ту же запись, сохраняя id и created_at |
| FR-04 | Удаление требует подтверждения с названием книги; отказ сохраняет запись, подтверждение удаляет только выбранную книгу |
| FR-05 | status принимает только want_to_read («Хочу прочитать»), reading («Читаю»), finished («Прочитано»); новое значение по умолчанию — want_to_read |
| FR-06 | Поиск проверяет вхождение строки в title или author без учёта регистра и внешних пробелов запроса; пустой запрос не ограничивает список |
| FR-07 | Фильтр содержит три статуса и «Все»; поиск и фильтр работают совместно по AND; отсутствие совпадений отличается от пустой библиотеки |
| FR-08 | Пробельные title/author не сохраняются; rating допускается только целым числом 1–5 при finished; ошибки связаны с соответствующими полями |
| FR-09 | Пока сохранение выполняется, повторная отправка заблокирована; ошибка сохраняет ввод и допускает повтор; успех явно объявляется; отмена вне сохранения закрывает форму без записи |
| FR-10 | При создании назначаются уникальный id и одинаковые created_at/updated_at; при изменении обновляется updated_at |
| FR-11 | На ДЗ5 запросы чтения и CRUD доступны только владельцу записи; попытка доступа другого пользователя отклоняется на уровне БД через RLS |

## Модель книги

| Поле | Планируемый тип | Обязательность и ограничения |
| --- | --- | --- |
| id | string (UUID) | Уникальное; назначается слоем сохранения, не вводится пользователем |
| title | string | Обязательное; trim, 1–200 символов |
| author | string | Обязательное; trim, 1–120 символов |
| status | BookStatus | want_to_read / reading / finished |
| rating | целое число или null | 1–5 только при finished, иначе null |
| notes | string или null | Необязательная заметка; trim, не более 1000 символов; пустая строка преобразуется в null |
| created_at | string (ISO 8601, UTC) | Назначается при создании; не изменяется при редактировании |
| updated_at | string (ISO 8601, UTC) | Назначается при создании и обновлении |
| user_id | string (UUID), отложенное поле | В ДЗ4 отсутствует в mock-модели; с ДЗ5 обязательно, владелец из проверенной сессии |

В ДЗ4 Book содержит первые восемь полей. Вход создания — title, author, status, rating, notes; вход редактирования использует те же поля, id передаётся отдельно. С ДЗ5 модель расширяется обязательным user_id. Времена и id не входят в редактируемые поля. UI-пустое значение оценки преобразуется в null до сохранения, а не в 0.

## Основные сценарии

1. **Добавить:** открыть форму → заполнить обязательные поля → при необходимости выбрать finished и rating → сохранить → увидеть сообщение и запись. Невалидный ввод оставляет форму открытой с ошибками.
2. **Изменить:** открыть запись → изменить статус/заметку → сохранить → увидеть обновлённую книгу. При переходе с finished на другой статус оценка очищается до null с пояснением.
3. **Удалить:** выбрать удаление → прочитать название → подтвердить или отменить. При ошибке удаления запись остаётся, доступен повтор.
4. **Найти:** ввести часть названия/автора → выбрать статус → увидеть пересечение условий или сообщение об отсутствии совпадений → очистить условия.
5. **Отменить добавление:** заполнить поля → нажать «Отмена» до отправки → вернуться к списку без новой записи.

## Ограничения и допущения

- Лимиты 200/120/1000 символов и целочисленная оценка — учебные допущения ДЗ2, подлежащие подтверждению на ДЗ3. Длина считается средствами JavaScript string.length; одинаковая проверка применяется в форме и при сохранении.
- В ДЗ4 данные находятся в памяти, сбрасываются при перезагрузке; mock-сохранение возвращает Promise и позволяет воспроизвести задержку/ошибку. LocalStorage не требуется.
- Во время сохранения отмена отключена: это предотвращает неопределённость, сохранилась ли уже запись. После ошибки отмена снова доступна.
- После успеха форма закрывается/сбрасывается, сообщение остаётся в родительском представлении; после ошибки ввод сохраняется.
- Повторяющиеся название и автор допустимы; уникальность определяется id. Не выполняются транслитерация и нечёткий поиск.
- На ДЗ5 авторитетные id/времена и владелец назначаются сервером/БД; frontend-валидация дополняется серверными ограничениями.
