# BookTrack — User Story Mapping

[Навигация](README.md) · [Описание проекта](project_description.md) · [ТЗ](technical_specification.md) · [Выбранный интерфейс](ui_concepts/ui_description.md)

## 1. Personas

- Анна, регулярный читатель: добавляет планы чтения и отмечает завершение; ценит короткую форму и понятные статусы.
- Сергей, возвращающийся читатель: после перерыва помнит часть названия или автора; ценит поиск, фильтр и сохранённые заметки.

Обе персоны используют роль «читатель» с одинаковыми правами. С ДЗ5 каждый работает только со своей библиотекой. Администратор и отдельные уровни доступа не нужны.

## 2. User Journeys — счастливые пути

| Путь | Последовательность | Результат |
| --- | --- | --- |
| Открыть библиотеку | Открыть приложение → дождаться загрузки → просмотреть карточки | Видны название, автор и статус; пустая библиотека предлагает добавление |
| Добавить книгу | Нажать «Добавить книгу» → ввести название и автора → выбрать статус → сохранить | Успех объявлен, новая запись создана один раз |
| Найти книгу | Ввести часть названия/автора → при необходимости выбрать статус | Показаны только совпадения; сброс возвращает исходный список |
| Изменить статус | Открыть редактирование → выбрать статус → сохранить | Та же книга получает новый статус; вне finished оценка очищена |
| Отредактировать запись | Открыть редактирование → изменить поля → сохранить | Изменена выбранная книга, id и дата создания сохранены |
| Удалить запись | Нажать «Удалить» → проверить название → подтвердить | Удалена только выбранная запись, показано подтверждение результата |

В ДЗ4 это локальная демонстрация. На ДЗ5 перед путями требуется действующая сессия; при её отсутствии открывается вход. OAuth2 относится к финальному ДЗ.

## 4. Истории и критерии приёмки

Критерии имеют стабильные ID AC-XX-Y; один ID соответствует одной строке Given–When–Then. Общие серверные отрицательные критерии AC-S-1–AC-S-3 применяются к каждой истории на ДЗ5. Полная связь с планируемыми тестами находится в разделе 15 ТЗ.

### US-01 — Просмотр библиотеки

«Как читатель, я хочу просматривать список книг, чтобы видеть свои планы и результаты чтения».

Приоритет: Must have. Требования: FR-01, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-01-1 | В библиотеке три книги с разными статусами | Открываю библиотеку | После загрузки вижу название, автора и русскую подпись статуса каждой книги |
| AC-01-2 | Библиотека пуста | Открываю библиотеку | Вижу «В библиотеке пока нет книг» и действие добавления |
| AC-01-3 | Загрузка отклоняется | Открываю библиотеку | Вижу сообщение об ошибке и «Повторить», пустая библиотека не объявляется |
| AC-01-4 | Повторная загрузка подготовлена успешно | Нажимаю «Повторить» после ошибки | Ошибка сменяется списком, дубликаты не появляются |

### US-02 — Добавление

«Как читатель, я хочу добавлять книгу, чтобы сохранить её в личном списке».

Приоритет: Must have. Требования: FR-02, FR-08, FR-09, FR-10, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-02-1 | Открыта новая форма с want_to_read | Ввожу « Мастер и Маргарита » и « Михаил Булгаков » и сохраняю | После успеха появляется одна книга без внешних пробелов; id уникален, created_at=updated_at, форма закрыта, успех объявлен |
| AC-02-2 | Форма открыта | Ввожу пробельное название или автора и сохраняю | Сохранение не вызывается; ошибки у полей, фокус на первом неверном поле |
| AC-02-3 | Сохранение ещё выполняется | Повторно отправляю форму или пытаюсь отменить | Повтор и отмена недоступны, есть «Сохранение…», создаётся максимум одна запись |
| AC-02-4 | Mock/API отклоняет сохранение до записи | Отправляю корректную форму | Поля сохранены, ошибки объявлены, повтор и отмена доступны; успех не объявлен |
| AC-02-5 | Запрос ещё не отправлен | Нажимаю «Отмена» и снова открываю добавление | Новая запись не создана, форма пуста и status=want_to_read |
| AC-02-6 | Новая форма | Ввожу title длиной 201, author 121 или notes 1001 после trim и сохраняю | Соответствующие поля отклонены; значения 200/120/1000 допускаются |

### US-03 — Редактирование

«Как читатель, я хочу редактировать книгу, чтобы исправлять сведения и сохранять свои заметки».

Приоритет: Must have. Требования: FR-03, FR-08, FR-09, FR-10, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-03-1 | Существует выбранная книга | Открываю редактирование, меняю автора и сохраняю | Форма содержит прежние значения; после успеха изменён только выбранный id, created_at сохранён, updated_at обновлён |
| AC-03-2 | Открыто редактирование | Очищаю автора или ввожу notes длиннее 1000 и сохраняю | Показана ошибка поля, исходная запись не изменена |
| AC-03-3 | Сохранение редактирования отклоняется | Отправляю изменения | Несохранённый ввод остаётся в форме, список не показывает ложный успех |
| AC-03-4 | Книга удалена в другой вкладке | Сохраняю ранее открытую форму | Вижу «Книга недоступна», новая запись не создаётся; могу закрыть форму и обновить список |

### US-04 — Удаление

«Как читатель, я хочу удалять книгу с подтверждением, чтобы убирать ненужные записи без случайной потери данных».

Приоритет: Must have. Требования: FR-04, FR-09, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-04-1 | Книга есть в списке | Нажимаю «Удалить», проверяю название и подтверждаю | До подтверждения запись остаётся; после успеха исчезает только выбранная книга |
| AC-04-2 | Открыто подтверждение | Нажимаю «Отмена» | Диалог закрывается, запись остаётся, фокус возвращается к действию |
| AC-04-3 | Удаление отклоняется до изменения данных | Подтверждаю | Книга остаётся, есть понятная ошибка и повтор; двойное подтверждение во время запроса заблокировано |
| AC-04-4 | Запись уже удалена | Подтверждаю удаление устаревшей записи | Вижу «Книга уже недоступна»; после обновления записи нет, другие книги не затронуты |

### US-05 — Изменение статуса

«Как читатель, я хочу менять статус чтения, чтобы понимать, какие книги запланированы, начаты и завершены».

Приоритет: Must have. Требования: FR-05, FR-08, FR-09, FR-10, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-05-1 | Книга имеет want_to_read | В редактировании выбираю reading и сохраняю | После успеха показано «Читаю», id и created_at сохранены, updated_at обновлён |
| AC-05-2 | Книга finished с rating=5 | Выбираю reading и сохраняю | До отправки вижу пояснение об очистке оценки; после успеха rating=null |
| AC-05-3 | Выбран finished | Сохраняю rating=0, 6 или 1.5 либо недопустимый status | Ввод отклонён с ошибкой; null, 1 и 5 допустимы для finished |
| AC-05-4 | Смена статуса отклоняется | Сохраняю новый статус | Список сохраняет прежний статус, форма хранит выбранное значение для повторной попытки |

### US-06 — Поиск

«Как читатель, я хочу искать книгу по названию или автору, чтобы быстро вернуться к сохранённой записи».

Приоритет: Must have. Требования: FR-06, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-06-1 | Загружена книга «Мастер и Маргарита», Михаил Булгаков | Ввожу « БУЛГАКОВ » или «мастер» | Показана эта книга по вхождению без учёта регистра и внешних пробелов |
| AC-06-2 | В библиотеке есть книги, но совпадений нет | Ввожу «несуществующая книга» | Вижу «Ничего не найдено» и сброс условий, данные не удалены |
| AC-06-3 | Есть поисковое ограничение | Очищаю запрос или оставляю пробелы | Возвращается весь список в рамках выбранного статуса |
| AC-06-4 | Исходная загрузка завершилась ошибкой | Ввожу поисковый запрос | Ошибка загрузки сохраняется, не показывается ложное «Ничего не найдено»; доступен повтор загрузки |

### US-07 — Фильтрация

«Как читатель, я хочу фильтровать книги по статусу, чтобы сосредоточиться на нужном этапе чтения».

Приоритет: Must have. Требования: FR-07, FR-11.

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-07-1 | Есть книги трёх статусов | Выбираю «Читаю» | В списке только reading; «Все» возвращает все статусы |
| AC-07-2 | Есть запрос «Булгаков» и разные статусы | Выбираю «Прочитано» | Показано пересечение поиска и finished; при пустом пересечении — «Ничего не найдено» |
| AC-07-3 | В состояние фильтра попал неизвестный код | Применяю фильтр | Значение сбрасывается на «Все»; приложение не падает и показывает все допустимые записи с учётом поиска |
| AC-07-4 | Библиотека пуста | Выбираю любой статус | Остаётся приглашение добавить первую книгу; отсутствие данных не выдаётся за ошибку |

### Общие защищённые сценарии ДЗ5

| ID | Given — начальное условие | When — действие | Then — результат |
| --- | --- | --- | --- |
| AC-S-1 | Сессия отсутствует или истекла | Выполняю любой путь US-01–US-07 | Данные скрыты, есть переход ко входу; операции не выполняются анонимно, ввод формы не отправляется до восстановления сессии |
| AC-S-2 | Действует сессия пользователя A, есть книга B | Пытаюсь прочитать или изменить книгу B прямым запросом | RLS не возвращает и не меняет чужие данные; UI не раскрывает владельца и сообщает недоступность |
| AC-S-3 | Сервер вернул некорректную структуру книги | Загружаю список или сохраняю изменение | Некорректный результат не попадает в UI как валидный; показана безопасная ошибка, успех не объявляется, доступно обновление |

В ДЗ4 защищённые сценарии описаны, но Auth/RLS не реализуются. Ошибки загрузки и записи воспроизводятся управляемыми mock Promise. Остальные серверные случаи проверяются в ДЗ5 по матрице ТЗ.
